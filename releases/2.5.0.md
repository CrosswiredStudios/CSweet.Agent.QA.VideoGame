# 2.5.0

- Report criteria can be marked `unverifiable` when their evidence needs a device, browser, network, registry, service or tool that is unavailable in the QA environment. Unverifiable criteria are never satisfied.
- If every command passes and only unverifiable criteria remain, QA returns Blocked with a `decision-required:v1` request naming the criteria, what is missing, and the options (defer or amend, or provide the environment). It no longer returns `failed`, which sent the unchanged candidate back to engineering with nothing to fix.
- Defects, failing commands, ordinary unmet criteria and any reported finding still fail back to engineering. Findings are reserved for defects; unperformable checks are recorded only as unverifiable criteria. Unverifiable-and-satisfied reports are rejected.
- Includes the unreleased 2.4.9 snapshot-provenance context. No new grants or network access.
