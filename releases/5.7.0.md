# 5.7.0

From Super Awesome Games ticket VGD2A04892DB-34 on 2026-11-12. QA wrote nine behavioral scripts in 45 minutes without a
verdict, then its own runner failed ("QA interaction evidence exceeds 4 MiB") and the stage blocked as "command failed".
A plain retry would have re-read the same failed run and blocked again. See the C-Sweet project doc
`claude/super-awesome-games-ticket-34-qa-behavioral-loop-evidence-cap-root-cause-2026-11-12.md`.

## Depth follows the ticket

- `GameQaBehavioralPolicy` reads the ticket's declaration. Criteria named by a `browser-interaction` verification
  (WorkManagement contracts 5.5.0) need live interaction evidence; with none declared, behavioral runs are optional.
- A pass on a ticket with declared interaction criteria needs a satisfied assertion citing each one, from this stage's runs.
- The prompt states the depth, the run budget, and that research spikes are judged as observation records.

## Runs converge on a verdict

- Behavioral runs are budgeted per stage: one per declared interaction criterion plus one correction (at most 8), two when
  none are declared, four for tickets planned before declarations. Each retry of the stage after a block adds one.
- When the budget is spent, `test_web_interactions` returns an instruction to submit the report instead of running.
- `save_qa_working_note` carries the model's plan from one compute callback to the next.

## Failures go to whoever can act

- A non-zero exit, timeout, truncation or lost result while preparing or running the authored test is a harness error:
  the run completes with the reason (including the stderr tail) and the model may run a corrected script. The same script
  is never replayed.
- A script that throws is recorded as `scriptError`, not as a page error, so it is not a product defect.
- A retry after a blocked attempt settles the in-flight run, or abandons it without replaying it, instead of re-reading
  the same failure.
- Identity, binding and receipt invariants are marked with the shared `agent-defect:v1` diagnostic, so the Producer
  reports them as needing an agent update rather than offering a plain retry.

## Runner

- `check(name, satisfied, evidence, { criterion, kind })`: checks cite the acceptance criterion they serve; `observation`
  checks record values and never fail the run.
- Evidence is kept in priority order (result, authored test, screenshot, trace) within the platform's 4 MiB export
  budget; anything left out is listed as `omittedEvidence`. Evidence size never fails a run.

## Prompt

- Engine- and API-specific rules (Phaser events, Web Audio `OscillatorNode`) moved out of the operating instructions and
  tool descriptions into engine notes, included only when the project uses Phaser or the criteria concern audio.
- New guidance: records are judged on coverage and honesty; a contradiction is reported once as a finding; a failed
  assertion is a defect unless QA's own expectation was wrong.
