# 5.6.0

Two fixes from Super Awesome Games on 2026-11-10.

## Missing browser compute is a wait, not a failure

Prism Break #20 was failed back to the engineer three times, with two more expired attempts, although QA found no product defect. QA's browser test (`test_web_build`) runs in project compute, and the project's Linux compute preparation was not ready. The tool returned that as an error, the model wrote a failed report, and the ticket went back to engineering, where nothing could fix it. This also queued every later ticket in the chain.

- Before any model call, a ticket that requires browser evidence and has no completed browser test checks the project's browser compute. If it is not ready, QA returns `awaiting-compute-preparation` with the owner-actionable reason and a retry time ten minutes out. There is no verdict, no model tokens are spent, and the ticket does not return to engineering. The platform re-dispatches QA and the check runs again.
- `test_web_build` checks readiness before staging a build. If compute is not prepared, the tool marks itself unavailable, ends the model's turn and QA returns the same wait. Any report submitted meanwhile is refused.
- Retained browser state is kept, so the same evaluation resumes once compute is ready.
- A QA browser environment that has failed is unchanged: it still blocks the ticket for a person to recover, because waiting would not re-provision it.
- The delivery-plan (aggregate) QA path does the same.

Needs a platform that accepts `awaiting-compute-preparation` (csweet, 2026-11-11). Install the platform first; an older platform rejects the outcome code.

## The ticket's declaration decides browser evidence

When planning declares `Verifications` (contracts 5.4.0), browser evidence is required exactly when it contains `browser-smoke`, a canvas exactly when that requirement says so, and declared viewport widths and WebGL must be observed. An explicit empty list means none. QA's prompt states what is required. The criteria-text rules apply only to tickets without a declaration.

Adds a direct `CSweet.WorkManagement.Contracts` 5.4.0 reference. SDK unchanged (5.12.1).
