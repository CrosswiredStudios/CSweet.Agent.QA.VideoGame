# 5.5.1

Release, Epic and Story QA now use the durable exact-source evidence journal and the same approved Chromium smoke, behavioral-test and script-retention helpers as ticket QA. Browser tool arguments select only repositories in the assigned candidate. Pending compute yields to platform continuation rather than model polling; source, candidate, planning, reviewer and execution identities fence recovery across replacement callbacks.

Bound aggregate QA to 65,536 context tokens and 8,192 output tokens per call, with a focused 24-iteration evaluation followed, when necessary, by an eight-iteration report phase. That phase exposes evidence reads and structured submission, with no shell or new browser experiments. Early prose or iteration exhaustion no longer silently skips report submission. Real defects and unverifiable checks remain blocking; completed browser failures cannot become a passing report.

Aggregate source snapshots remain immutable and every reported validation retains its repository and exact commit binding. Task QA journal identities and existing browser-state keys remain compatible. No new capabilities, grants or network permissions are requested.

Requires the matching platform quality-compute continuation fix and SDK 5.10.1. Publish/install through Installed Agents, restart C-Sweet, then retry the existing failed quality check through Delivery > Retry validation. Preserve accepted build readiness and completed task/sprint history.
